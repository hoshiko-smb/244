# 学校規模 × 競合情報の統合（綜合キャリアオプション様 27卒 学校訪問）

訪問シート（Google ドキュメント／学校ごとのタブ）に散らばっている「学校規模」と「競合の訪問状況」を、
アポイント＆訪問管理表の **「27卒_アポイント＆訪問管理」タブだけ** に追記するためのツール一式です。
他のタブ・既存の A〜AM 列には一切書き込みません（xlsx はシートXMLだけを差し替え、他の148ファイルはバイト一致のままコピー）。

## 追加される列（AN〜AW）

| 列 | 見出し | 中身 |
|---|---|---|
| AN | 学校規模（1学年） | 「1学年○○人程度」。補足が必要な場合だけ（）で内訳 |
| AO | AGIC訪問 | エイジェックの訪問 あり／なし／不明 |
| AP | 他社訪問 | AGIC以外の人材系競合 あり／なし／不明 |
| AQ | 訪問競合社名（AGIC以外） | 判明した社名。社名が聞けていない場合は「社名不明」 |
| AR | 競合情報時点 | 判断に使った最新の訪問日 |
| AS / AT | 根拠 | どの訪問シート・前回調査のどの記述から判断したか（抜粋） |
| AU | 抽出メモ | 要確認の理由（規模をメモから推定／新旧で有無が食い違い／訪問シートなし 等） |
| AV | 担当確認 | 未確認／OK／要修正（プルダウン） |
| AW | 修正内容 | 営業担当が正しい値を記入 |

判定の考え方
- **あり**: 社名の言及があり、同じ文の中で否定（来ていない・訪問なし 等）されていない
- **なし**: 「エイジェックは来ていない」等の明示、または「人材系の訪問はない」等の全体否定があり、他に訪問ありの情報がない
- **不明**: 記載なし／聞けていない／情報が割れていて断定できない
- 競合情報は **2026-09-30 までの訪問分** で確定（`--cutoff` で変更可）。前回調査（「訪問学校の競合調査」「他社集約用」タブ、AJ列）も合わせて使う

## 訪問シートのテンプレート（4パターン）と読み取り方

| | テンプレート | 学校規模 | 競合情報 |
|---|---|---|---|
| ① | 標準「学校訪問シート【原本】」 | 「最上級生の全体人数」欄 | 「BPOや新卒派遣の引き合い」欄 |
| ② | 競合深掘り版（2026年〜・太字） | 同上 | 「★よく来ている競合他社」の **その他（…）欄**、★27卒の案内時期 ほか |
| ③ | 旧版（2024年度） | 同上 | 「派遣会社はきてるか？（何社くらい？）」欄 |
| ④ | 人数欄が空でメモだけのもの | メモ本文から読み取り（`size_overrides.json` の `row:N`） | メモ本文で社名が出てくる箇所 |
| ⑤ | 競合欄削除版（No.4・2026年8月〜「（競合情報削除）」原本） | 同上 | 競合はMicrosoft Formsに入力する運用のためシート上に欄なし → メモ本文の社名のみ |

②の7社リスト（ウィルオブワーク／エイジェック／…）はエクスポートするとチェック状態が残らない（150件中138件が7社すべて残ったまま）ため、
社名リスト自体は使わず「その他（…）」の記入だけを回答として扱います。記入例（「例：…」）も除外します。

## トークンを抑えつつ精度を保つ仕組み

1. `extract_visit_sheets.py` … タブごと・訪問日ごとに、決まった欄だけを機械的に切り出す（AIに全文を読ませない）
2. `match_rows.py` … 管理表の行を訪問シートのタブに突合（AB列URLのドキュメント内を優先、大原学園の正式名称⇔タブ名などの表記ゆれを吸収）。突合できないものは `manual_matches.json`。
   同じ学校の訪問履歴が別のシート（No.1〜No.4）に続いている場合は、タブ名がほぼ一致するものを合算して最新の訪問を使う
3. `school_size.py` … 「約400人」「800名弱」「140〜150名」などは自動整形。「大学800名・短大200名」のような複合記述（約100件）と、人数欄が空でメモにだけ書かれているもの（27件）だけを人／AIが読んで `size_overrides.json` に登録（`rowfix:N` は複数回の訪問記述を合わせて読む必要がある行の補正）
4. `competitors.py` / `build_integration.py` … 社名辞書＋否定表現で あり／なし／不明 を判定し、根拠の抜粋を残す
5. `write_xlsx.py` … 27卒タブだけに書き込む
6. `summarize.py` … エリア × 規模 × AGIC の集計と攻略候補リスト

次回の追加更新では、新しく増えた複合記述だけを `size_overrides.json` に足せばよく、全件をAIに読ませ直す必要はありません。

```bash
./run.sh 管理表.xlsx 訪問シートtxtのフォルダ 出力フォルダ 2026-09-30
```

## 営業チームでの確認フロー（フィルタービュー）

`apps_script/integration.gs` を本番スプレッドシートの Apps Script に貼り付けて使います（「サービス」で Google Sheets API を追加）。

1. `importIntegration` … 統合済みファイルの AN〜AW を本番シートへ写す。**行番号と学校名（H列）が一致する行だけ**に書き、行が動いていれば学校名で探し直す。担当者が既に「OK／要修正」を付けた行の AV・AW は上書きしない
2. `setupCheckColumn` … AV列に「未確認／OK／要修正」のプルダウン
3. `createReviewFilterViews` … 訪問者ごとに「【確認用】◯◯」フィルタービュー（自分の訪問校で、まだOKになっていない行だけ）と、「【戦略】AGIC訪問あり」「【戦略】AGIC不明（要ヒアリング）」を作成。同名のビューは作り直し、他のビューには触れない

各担当は自分の「【確認用】」ビューを開き、AN〜AQ を見て正しければ AV を「OK」、違えば「要修正」にして AW に正しい内容を書く →
取りまとめ役が「要修正」の行を AN〜AQ に反映して「OK」にする。
